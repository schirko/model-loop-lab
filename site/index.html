DATA SCIENCE PROJECT · COLORADO FOREST COVER, 581,012 PLOTS

Can AI build better AI?

A program that builds forest-cover models, tests them on Colorado forest plots they have never seen, keeps the best and improves them, with no person choosing the settings. Then a second loop where models learn only from data other models made up, to see where the idea breaks. Built from free public data and worked through in four notebooks.

The project in plain English

The question. New AI systems are increasingly built with help from older ones. Can a program design, test and improve its own models, and does it get better each round? And what happens when models learn from data that other models made up instead of from the real world?

The data. 581,012 plots of the Roosevelt National Forest in northern Colorado, each a square about 30 meters on a side, described only by map measurements: elevation, slope, distance to water, roads and past fires, wilderness area and soil type. The job is to say which of seven tree covers grows there, such as Spruce/fir or Lodgepole pine.

What we know so far. A plain decision tree with no tuning gets 77.2% of plots right that it has never seen, against 48.8% for always guessing the most common tree. It memorizes its training plots (100% on those) and mixes up neighbors: trees that grow at the same elevations on the same soils. That 77.2% is the number every later model has to beat.

What comes next. Notebook 02 runs the improvement loop for 20 generations. Notebook 03 races it against Optuna, a standard tuning tool, and against random guessing. Notebook 04 runs the copy-of-a-copy loop and measures what is lost. Their findings will be added here as each one is finished.

Key findings so far

  • Map measurements carry real information. A plain decision tree is right on 77.2% of held-out plots; always guessing Lodgepole pine is right on 48.8%. The 28-point gap is what elevation, soil and the rest are worth. Notebook 01, Step 5
  • The plain tree memorized its training plots. It scores 100% on the 15,000 plots it learned from, by asking up to 33 yes/no questions and ending in 2,341 final answers, about one for every six training plots. On new plots it is wrong 1,141 times out of 5,000. That 23-point gap is overfitting. Notebook 01, Step 7
  • The common trees are fine; Aspen and Douglas-fir are not. The tree finds 80% of Lodgepole pine and 77% of Spruce/fir plots, but only 52% of Douglas-fir and 44% of Aspen. Notebook 01, Step 8
  • The mistakes are between neighbors. 21% of Spruce/fir plots are called Lodgepole pine and 16% of Lodgepole pine are called Spruce/fir; because those two are 85% of the forest, that pair causes most of the errors. Aspen is called Lodgepole pine 44% of the time. Krummholz, rare but with only one look-alike, does well. Notebook 01, Step 9
  • Rarity alone doesn't explain the weak spots. Krummholz has only 177 held-out plots yet is found 77% of the time, as often as the common types. What hurts a cover type is having a look-alike neighbor, not just being rare. Notebook 01, Steps 8 and 9

Findings from notebooks 02 to 04 (how far the loop climbs, how it compares with Optuna, and what model collapse costs) will be added here as each notebook is finished.

Words used on this page

WordWhat it means here
ModelA set of rules learned from data that turns a plot's map measurements into a guess of which trees grow there.
Decision treeA model that asks a chain of yes/no questions ("Is the elevation above 3,000 m?") until it reaches an answer.
AccuracyThe share of plots the model labels correctly.
Held-out plots5,000 plots set aside and never shown to a model while it learns. Every score on this site comes from these same plots.
BaselineThe score of a plain model with no tuning: the number to beat. Here, 77.2%.
OverfittingMemorizing the training plots instead of learning patterns that carry over to new ones.
RecallOf the plots that really are a given cover type, the share the model found.
GenerationOne round of the improvement loop: build several models, score them, keep the best.
Synthetic dataMade-up data produced by a model, meant to look like the real thing.
Model collapseWhat happens when models learn only from earlier models' made-up data and lose touch with the real data.

How it was done

  1. Collected the Forest Covertype data (U.S. Forest Service and Colorado State University) with scikit-learn's fetch_covtype: 581,012 plots, 54 map features, 7 cover types.
  2. Sampled and split it fairly: 20,000 plots drawn so every cover type keeps its exact share, then 15,000 for training and 5,000 held out, with no plot on both sides. One random seed (42) drives every step, so every result repeats exactly.
  3. Scored every model the same way, through one shared function: train a fresh copy, then measure accuracy on the same 5,000 held-out plots.
  4. Measured the baseline: a plain decision tree, against guessing and against its own training plots, broken down by cover type and by which cover types get confused.
  5. Tested. 56 automated tests check the sampling, the split, the scoring, the files the site reads, that every page carries the portfolio's back bar and noindex tag, and that this page quotes the same baseline as the saved results. They run on every change.
  6. Published this site from the notebooks' saved results with one script, so every number and chart matches the latest run, and each finished notebook appears as a web page.

Limits. One dataset, from one forest. Accuracy is a single overall score, so the rare cover types count for little in it; the per-cover-type results are there to show what it hides. The loops are small versions of the real thing, built to show the mechanism, not the scale of large AI systems.

The analysis, step by step

Four notebooks walk through the whole project in order, written for a reader who is smart but not necessarily an analyst. Each step follows the same pattern: what we're looking for, the code and its result, how to read it, what it means, and what's next and why.

  1. The data, and how good a plain model is The forest data and its lopsided cover types, a fair sample and split, guessing against a plain tree, the 77.2% baseline, overfitting, and which trees get confused with which. Ten steps. Read it
  2. The evolution loop: can a program find better models on its own? Build ten models, keep the best three, change them a little, repeat for 20 generations. How far it climbs above 77.2%, which settings win, and whether it fixes the overfitting and the neighbor mix-ups. In progress
  3. The search race: is the loop better than the alternatives? The loop, Optuna and random guessing each get the same 200 tries on the same plots. Who finds a good model first, and who ends highest. Planned
  4. Model collapse: what happens when models learn only from other models? Each generation learns only from data the previous one made up. How accuracy on real plots and the variety in the data drain away, and which trees vanish first. Planned
